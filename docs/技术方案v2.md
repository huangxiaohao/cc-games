## 二、移动端适配方案

**基准：设计稿宽度 750px，1rem = 20px**

```javascript
// main.jsx 顶部执行
function setRem() {
  const rem = document.documentElement.clientWidth / 750 * 20;
  document.documentElement.style.fontSize = rem + 'px';
}
setRem();
window.addEventListener('resize', setRem);
```

**换算规则：设计稿 px ÷ 20 = rem**

```
设计稿 100px → 5rem
设计稿 200px → 10rem
设计稿 750px → 37.5rem
```

**约定：**
- 所有 width / height / top / left / font-size / padding / margin 全用 rem
- 禁止写 px（border: 1px 除外）
- 背景图 `width: 100%; height: auto`，高度永远不写死

## 三、页面布局核心模式

每个页面：全屏背景图撑开高度，交互元素绝对定位叠上去。

```
┌─────────────────────┐
│   <img> 背景图       │  ← width:100%, height:auto，撑开页面
│                     │
│  ┌──────────┐       │  ← 绝对定位热区（透明，只负责点击）
│  │ 点击热区  │       │
│  └──────────┘       │
│                     │
│  <span> 动态数据     │  ← 绝对定位文字/图表
└─────────────────────┘
```

**热区定位公式（百分比自适应）：**
```css
.page {
  position: relative;   /* 热区定位的参考系，必须有 */
}

.img {
  width: 100%;
  height: auto;        /* 保持设计稿原始比例，不用 height: 100vh */
  display: block;
}

.hotArea {
  position: absolute;
  /* 使用百分比定位，基于背景图尺寸自适应，跨设备一致 */
  top: X%;             /* 设计稿标注的 top px ÷ 图高 px × 100% */
  left: X%;            /* 设计稿标注的 left px ÷ 图宽 px × 100% */
  width: X%;            /* 热区宽度 px ÷ 图宽 px × 100% */
  height: X%;           /* 热区高度 px ÷ 图高 px × 100% */
  cursor: pointer;
  /* 开发调试时加：background: rgba(255,0,0,0.2); */
}
```

> ⚠️ **禁止用 rem 定位热区**——不同设备视口宽度差异巨大，固定 rem 在宽屏设备（iPad/PC）上位置会严重偏移。百分比基于背景图比例，自适应所有机型。

## 四、Tab 方案

Tab 标签已固定在背景图上，不需要渲染 Tab 组件。

实现方式：每个 Tab 对应一个绝对定位热区 + 一个内容区。

```jsx
const [activeTab, setActiveTab] = useState('a');

{/* Tab 热区：对准图片上的 tab 位置 */}
<div className={styles.tabA} onClick={() => setActiveTab('a')} />
<div className={styles.tabB} onClick={() => setActiveTab('b')} />

{/* 内容区：只显示当前 active 的 */}
{activeTab === 'a' && <PanelA />}
{activeTab === 'b' && <PanelB />}
```

切换不保留状态，组件卸载重建。

## 五、钉钉免登流程

```
应用启动
    ↓
dd.ready() 回调触发
    ↓
dd.runtime.permission.requestAuthCode()  →  拿到 authCode
    ↓
POST /api/user/dingtalk-login { authCode }  →  后端换取用户信息 + token
    ↓
存入 Context（userName / userId / token 等）
    ↓
进入首页
```

**关键点：**
- 免登在应用入口统一处理，用 Context 全局共享用户信息
- 免登未完成前显示空白或 loading，不渲染任何页面
- 后续所有接口请求带上 token（在 `request` 函数统一注入 header）

## 七、OSS 上传流程

```
用户选择文件（图片或视频）
    ↓
POST /api/oss/token  →  { host, key, policy, OSSAccessKeyId, signature }
    ↓
XHR 直传 OSS（FormData），监听 progress 事件显示进度
    ↓
返回文件 URL，存入表单数据
```

## 八、注意事项

1. **钉钉环境判断**：开发阶段在 PC 浏览器跑，dd.ready 不会触发，需加环境判断 mock 掉免登流程
2. **背景图预加载**：App 启动时把所有背景图提前加载，防止切页白屏
3. **热区调试**：开发时所有热区加红色半透明背景，上线前统一去掉
4. **OSS CORS**：bucket 需配置允许前端域名的跨域规则，否则直传会报错
5. **视频上传大小**：建议前端限制视频文件大小（如 100MB），超出给提示
6. **微信/钉钉 input[type=file]**：`accept="image/*,video/*"` 在部分安卓钉钉版本可能失效，需真机测试
